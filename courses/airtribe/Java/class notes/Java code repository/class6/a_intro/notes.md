# What are Design Principles?

## Definition
Design principles are **fundamental guidelines** that help software developers create code that is:
- **Maintainable**: Easy to modify and extend
- **Scalable**: Can handle growth in data and functionality
- **Reusable**: Components can be used across different parts or projects
- **Robust**: Less prone to errors and bugs

## Why are Design Principles Important?
1. **Enhance Code Quality** - Improves readability and understanding
2. **Facilitate Collaboration** - Makes it easier for teams to work together
3. **Promote Best Practices** - Encourages following industry standards
4. **Support Long-Term Success** - Ensures the application can evolve over time

## Key Design Principles (what we'll cover)
| Principle | One-Liner |
|-----------|-----------|
| **DRY** | Don't Repeat Yourself |
| **KISS** | Keep It Simple, Stupid |
| **YAGNI** | You Aren't Gonna Need It |
| **SOLID** | 5 principles (SRP, OCP, LSP, ISP, DIP) |
| **Composition over Inheritance** | Prefer "has-a" over "is-a" |

## Design Principles vs Design Patterns

| Aspect | Design Principles | Design Patterns |
|--------|------------------|-----------------|
| **Scope** | High-level, abstract guidelines | Concrete, specific solutions |
| **Application** | Guide overall design & architecture | Address specific design problems |
| **Flexibility** | Broadly applicable across contexts | Applied to particular problems |
| **Example** | "A class should have one responsibility" | "Use Observer pattern for event handling" |

> **Think of it this way:** Principles tell you *what* to aim for. Patterns show you *how* to achieve it.
