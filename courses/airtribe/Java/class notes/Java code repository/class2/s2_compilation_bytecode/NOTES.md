# Java Compilation & Bytecode

## The Compilation Process

```
  HelloWorld.java          (Source code you write)
        │
        ▼  javac (Java Compiler)
  HelloWorld.class         (Bytecode — intermediate form)
        │
        ▼  java (JVM)
  Machine Code             (Native code for your OS)
```

## What is Bytecode?
- An **intermediate representation** of your Java source code
- Generated by the Java compiler (`javac`)
- **Platform-independent** — the same `.class` file runs on any OS
- It is NOT human-readable — it's a set of instructions for the JVM

## Compilation Step-by-Step
1. **Write** your code in a `.java` file
2. **Compile** with `javac MyFile.java` → produces `MyFile.class`
3. **Run** with `java MyFile` → JVM reads the bytecode and executes it

## Viewing Bytecode
You can disassemble a `.class` file to see the bytecode:
```bash
javap -c MyFile.class
```
This shows the actual JVM instructions (e.g., `aload_0`, `invokevirtual`, `return`).

## Why Bytecode Matters
- **Platform Independence** — compile once, run anywhere with a JVM
- **Security** — bytecode is verified before execution
- **Performance** — JIT compiler can optimize bytecode at runtime

## Compile & Run Commands
```bash
javac HelloWorld.java      # Compile → generates .class file
java HelloWorld             # Run → JVM executes the bytecode
javap -c HelloWorld.class   # Inspect → see the bytecode instructions
```
